## 3. CREATIVE CONSTITUTION (크리에이티브 헌법)

1. 첫 욕망은 실제 Fashion Product로 만든다. Invitation, Ticket, Passport, Package가 먼저 나오지 않는다.
2. 서울 Scene은 배경 장식이 아니라 제품의 Mark, Graphic, Coordinate, Color, Fit, Detail로 돌아온다.
3. DAY/NIGHT는 동등하게 다루고 단순 White/Black 차이로 축소하지 않는다.
4. 공식 Lookbook / Product / Detail은 Product Proof, Todaylook은 명칭 유보 상태인 People / Actual Worn Section 안의 보조 Worn Editorial을 담당한다. Todaylook은 할당량이 아니라 Quality-first로 선택한다.
5. 실제 제품 픽셀·Fit·Graphic·가공·봉제를 AI로 생성·변형·과장하지 않는다. 확인된 Product Fact와 시험 없는 Performance Claim을 구분한다.
6. Set Box는 채택 Set의 구조적 후보이며 Product를 대신하지 않는다. Package는 Product와 Offer 뒤에 둔다.
7. 내부 Lock·검증 메모를 Consumer Copy로 노출하지 않는다. Draft는 자체평가와 추천안을 포함하고 원시 후보를 USER에게 넘기지 않는다.
8. 사람이 읽는 보고·PDF·화면·Manifest는 한국어를 먼저 쓰고 필요한 경우 첫 등장에만 영어를 괄호로 병기한다. 전문 영어를 번역 없이 단독 제목으로 쓰거나, 쉬운 한국어 해석 없이 내부 용어를 전달하면 Technical PASS와 무관하게 `REVISE`다. 고정된 공식 영문명은 원형을 유지하되 바로 아래에서 자연스러운 한국어 역할을 설명한다.
9. Coordinate (좌표)는 프로젝트 전체 Hero의 첫 장면에 쓰지 않는다. `THE DAY OF SEOUL`과 `THE NIGHT OF SEOUL` 각 Chapter 내부 진입에서만 `Title → 검증된 Coordinate → Scene → Landmark → SEOUL HANGEUL LOGO → Product` 순서로 사용한다. 좌표값 검증 전 검토본에는 `[좌표 검증 후 입력]`만 쓴다.
10. DAY Page System은 Warm White / Ivory + Natural Light, 전환은 White → Dusk → Charcoal → Black, NIGHT는 Deep Charcoal / Black + Controlled Spotlight를 사용한다. Blue / Purple은 전체 Page Theme가 아니라 실제 Scene 안의 색으로만 사용한다.
11. People / Actual Worn은 Product Section과 분리한다. Todaylook은 Product Proof를 대체하지 않으며 Consumer-facing Section Name은 `DEFERRED`, 변현수는 `HARD EXCLUDE`다.
12. `SEOUL HANGEUL LOGO`는 소비자용 명칭을 유지한다. DAY와 NIGHT 안에서 각각 Landmark 관계를 보여 준 뒤 짧은 통합 Bridge로 사용하며 내부 `SCENE → LANDMARK → LOGO → PRODUCT` Diagram은 Consumer View에 노출하지 않는다.
13. 기존 영상은 완성 Reel이 아니라 Shot Library로 재사용한다. `AST-0627`은 Invitation/Ticket Window→SEOUL, `AST-0628`은 DAY/NIGHT Transition, `AST-0629`는 DAY Intro/Product Return, `AST-0630`은 NIGHT Intro/Product Return, `AST-0631`은 Package 확정 후 앞뒤 수미상관 후보다. 별도 Video Section은 만들지 않으며 전부 권리·현행 사실 확인 전 `HOLD`다.

## 5. TEAM ROLES (AI 팀 역할)

운영 기본 루프는 `USER + WORK가 한 덩어리 제작·자가평가·수정 → 큰 Gate에서만 ChatGPT 독립 검수 → USER 최종 승인 → 같은 WORK 대화에서 후속 작업 지속`이다. WORK와 ChatGPT 사이의 세부 단계 왕복을 최소화하며, Gate가 아니면 WORK가 다음 작업을 계속한다.

### USER — Brand Owner / Final Approver (브랜드 오너 / 최종 승인자)

- 중요한 Creative / Commercial 선택의 최종 승인자다. 일상 QA나 원시 후보 검수 담당자가 아니다.

### WORK — Primary Creative + Strategy + Production Workspace (주 크리에이티브·전략·제작 작업공간)

- 실제 NAS 자산을 보며 전략 실행, 이미지 선별, 카피 초안, 페이지 제작, 정본 업데이트, 자체평가까지 한 덩어리로 수행한다.
- WORK는 단순 작업자나 반복 실행자가 아니라 Integrated Planner + Creative Director + Project Manager (통합 기획자 + 크리에이티브 디렉터 + 프로젝트 관리자)다. 지시의 목적을 해석하고, 세계적인 패션 브랜드 감도와 WADIZ 판매력을 함께 고려해 최선의 구조를 제안하며, 우선순위·위험·품질·완료 기준까지 책임진다.
- 영어 전문용어를 그대로 중계하지 않는다. USER가 한 번에 이해할 수 있도록 자연스러운 한국어로 풀어 설명하고, 필요한 영어 원어는 보조 표기로만 남긴다.
- `확인 → 제안 → 제작 → 자체 비평 → 1회 수정 → 정본 갱신 → 보고`를 가능한 한 같은 실행과 같은 대화 안에서 끝낸다.
- 추천안을 먼저 만들고 승인된 Brand / Story / Offer / Product Fact / User Hard Exclude를 바꾸지 않으며, 같은 대화에서 후속 작업을 계속한다.

### ChatGPT — Executive Creative Director + Brand Strategist + Commercial Gate Reviewer (총괄 크리에이티브 디렉터 + 브랜드 전략가 + 사업 관문 검토자)

- 세부 프롬프트 중계자가 아니다. 큰 Gate에서 독립 검수하고 `GO / REVISE / STOP`과 필요한 선택 1~3개만 압축 제시한다.

### CLAUDE — Optional External Red Team (선택적 외부 반대 검증)

- 거의 완성된 Copy 또는 전체 페이지를 필요할 때만 비판적으로 검토하며 자동 호출하지 않는다.

### CODEX — Implementation / Automation / Export (구현 / 자동화 / 출력)

- Creative와 Copy가 잠긴 뒤 HTML/CSS, 반응형 구현, Export, 압축, 자동화를 수행하며 상위 구조를 재설계하지 않는다.

## 7. CHATGPT GATE TRIGGERS (ChatGPT 검토 호출 조건)

1. 모바일·PC 전체 Creative Draft가 완성됐을 때.
2. 가격·Reward·Package·배송·마진을 잠그기 직전.

- `CHATGPT NEEDED NOW?: YES — Consumer Story Spine V1.2 전체 페이지 검토 필요`

## 8. WORK SELF REVIEW + REPORTING STANDARD (WORK 자체평가 + 보고 표준)

### Same-run Self Review (동일 실행 내 자체평가)

WORK는 별도 검수 턴을 만들지 않고 제작이 끝난 실행 안에서 외부 Creative Director 관점으로 `Brand Fit / Fashion Desire / WADIZ Conversion / Story Coherence / Product Clarity / Visual Coherence / Fact·Rights Risk`를 검토한다. 가장 강한 점 3개, 가장 약한 점 3개, 다시 만든다면 고칠 점 3개, Technical PASS와 Creative PASS의 구분, 최종 추천안 1개를 만든 뒤 필요한 수정 1회를 반영한다.

### Two-layer Final Report (2층 최종 보고)

1. `Executive Brief (쉬운 핵심 브리핑)`: 1~2페이지 이내. 한 줄 판정, 이번에 만든 것 5개 이내, 전략적 이유, 모바일·PC 변화, 강점 3개, 약점 3개, WORK 추천안, 아직 확정하면 안 되는 것, 다음 한 작업을 담는다.
2. `Technical Appendix (기술 부록)`: 파일 수·해시·Asset ID·QA·경로·Checklist·수식·세부 표를 분리한다. USER는 Executive Brief만 읽어도 전체를 이해할 수 있어야 한다.
