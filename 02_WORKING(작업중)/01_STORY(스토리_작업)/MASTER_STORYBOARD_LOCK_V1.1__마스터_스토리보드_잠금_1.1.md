기준 우선순위는 다음과 같다.

1. 사용자의 최신 보정 결정: 기존 스토리 유지, 성공 사례의 기능만 선택 적용

## 1. 전체 판정

### `STORY KEEP / FUNCTIONAL REINFORCEMENT / V1.1 LOCK`

현재 큰 흐름은 유지한다.

`GALLERY HERO → PROJECT / COLLECTION → INVITATION → DAY → DAY→NIGHT → NIGHT → ONE SEOUL → PRODUCT → PEOPLE → XXX STUDIO / ARCHIVE / CURRENT PROJECT → WHY → OFFER / PACKAGE / COMMERCE → FINAL`

문제는 구조 자체보다 다음 실행 공백이다.

1. DAY와 NIGHT의 같은 역할 페어가 부족하다.
2. T-SHIRT·SWEATSHIRT·CAP의 제품 증거가 균등하지 않다.
3. People이 Fashion Desire를 만들 만큼 편집되지 않았다.
4. `현재 제작 과정`으로 오해될 수 있는 Maker 역할이 잘못 잡혀 있다.
5. Offer·생산·Package·배송이 미확정이라 Why와 Commerce가 아직 비어 있다.

따라서 V1.1은 13개 구조를 다시 만들지 않고 Product·Trust·Commerce를 성공 사례 수준으로 보강한다.

## 5. 매크로별 실행 잠금

### 01 — GALLERY HERO

- Reference principle: ADERERROR의 Editorial/Product Fact 역할 분리만 적용한다.
- Required asset role: `HERO` — DAY와 NIGHT, 서울 세계관, 실제 제품군을 한 화면에서 인지시키는 최종 Hero.
- Native Text:
  - `XXX STUDIO / EXPERIENCE`
  - `REPUBLIC OF KOREA TOUR · CHAPTER 01`
  - `SEOUL : DAY & NIGHT`
- Visual grammar: 설명보다 욕망. DAY/NIGHT가 같은 무게로 보이고 T-SHIRT·SWEATSHIRT·CAP의 실제 제품 단서가 있어야 한다.
- Gate: Final AI Hero, 모바일 Crop, 실제 제품 오인, 권리 확인 전 `TEMPORARY HERO` 상태를 유지한다.

### 02 — PROJECT / COLLECTION FRAME

- Reference principle: Color Your Seoul의 도시→시각 언어→상품 연결을 적용하되 관광 서사는 제외한다. 호담국의 세계관→리워드 명료성을 DAY/NIGHT 제품축으로 변형한다.
- Required asset roles: `PROJECT IDENTITY`, DAY/NIGHT 실제 제품 Overview 또는 식별 가능한 Product Cue.
- Native Text — V0.8 유지:
  - `REPUBLIC OF KOREA TOUR`
  - `EXPERIENCE SCENE OF KOREA`
  - `CHAPTER 01 — SEOUL : DAY & NIGHT`
  - **REPUBLIC OF KOREA TOUR는 한국의 장면을 XXX STUDIO의 방식으로 경험하는 패션 프로젝트입니다. 첫 번째 목적지 서울을 DAY와 NIGHT, 두 장면으로 펼칩니다.**
  - **티셔츠·스웨트셔츠(맨투맨)·캡으로 만나는 서울의 낮과 밤.**
  - DAY / NIGHT의 T-SHIRT·SWEATSHIRT·CAP 제품명 6개
- Visual grammar: Hero 설명 반복 금지. Project Identity 다음에 DAY/NIGHT와 제품군을 즉시 확인시킨다. 동일한 6개 카드 Grid는 사용하지 않는다.
- Gate: 실제 제품 이미지가 부족하면 AI나 텍스트 Placeholder로 제품 증거를 대체하지 않는다.

### 03 — INVITATION BRIDGE

- Reference principle: 기존 XXX STUDIO의 Invitation 서사를 그대로 유지한다. 외부 사례의 여행·기념품 문법은 적용하지 않는다.
- Required asset role: `INVITATION` — Envelope → Ticket → Window → SEOUL의 3–4 Frame Static Sequence 또는 저해상도 Local-only Motion.
- Native Text:
  - `INVITATION TO KOREA TOUR`
  - `FIRST DESTINATION`
  - `SEOUL`
- Visual grammar: 넓은 여백 속 단일 이동 경험. Package 전체를 미리 보여주지 않는다.
- Gate: QR, 과거 시즌, 지도, 영상, 인물, 음원 권리 확인 전 Public Export에 사용하지 않는다.

### 04 — THE DAY OF SEOUL

- Reference principle: Color Your Seoul과 IISE의 전환 원리를 별도 설명 없이 화면 안에서 적용한다. thisisneverthat의 Lookbook→Product 연결을 사용한다.
- Required asset roles: `DAY SCENE`, `DAY TRANSFORMATION`, `DAY LOOKBOOK`, DAY Product Detail.
- Same-role pair requirement: NIGHT의 Scene, Transformation, Lookbook, Product와 같은 역할을 반드시 맞춘다.
- Native Text:
  - `THE DAY OF SEOUL`
  - `BUKCHON · SEOUL`
  - `N SEOUL TOWER`
  - 좌표는 검증 완료 후만 노출
  - **전통과 현대가 한 시야에 겹치는 서울의 낮.** — `COPY REVIEW FLAG`: V0.8 문구는 삭제·재작성하지 않고 유지하되, 레퍼런스 판정상 상투성 검토가 필요하므로 Final Copy 잠금 아님
- Visual grammar: Warm White / Ivory, 자연광, 공기감, 수평 리듬. `Scene → Landmark Cue → DAY 서울 Logo → Product Detail → Lookbook`을 한 번만 통과한다.
- Gate: 실제 Scene·좌표·랜드마크·제품 SKU 일치와 권리 확인.

### 05 — DAY → NIGHT

- Reference principle: 외부 스타일이 아니라 시간 변화라는 기능만 사용한다.
- Required asset role: `TRANSITION` — White / Dusk / Black 또는 같은 장면의 시간 변화 3–5 Frame.
- Native Text: Body Copy 0.
- Visual grammar: Gradient Card 1장 금지. 페이지 배경, 장면, 명암, 이미지 길이가 점진적으로 바뀌어야 한다.
- Gate: 실제 변화가 없는 임시 레이아웃은 최종 자산으로 승인하지 않는다.

### 06 — THE NIGHT OF SEOUL

- Reference principle: DAY와 같은 역할을 맞추고, 편집 리듬만 다르게 한다. IISE의 모티프→디테일 전환과 thisisneverthat의 Lookbook→Product 연결을 적용한다.
- Required asset roles: `NIGHT SCENE`, `NIGHT TRANSFORMATION`, `NIGHT LOOKBOOK`, NIGHT Product Detail.
- Same-role pair requirement: DAY의 Scene, Transformation, Lookbook, Product와 같은 역할을 반드시 맞춘다.
- Native Text:
  - `THE NIGHT OF SEOUL`
  - `JAMSIL · SEOUL`
  - `LOTTE WORLD TOWER`
  - 좌표는 검증 완료 후만 노출
  - **빛과 어둠이 수직으로 쌓이는 서울의 밤.**
- Visual grammar: Deep Charcoal / Black, 통제광, 밀도, 수직 리듬. Neon·Cyberpunk UI와 DAY의 검정 복사본을 금지한다.
- Gate: 실제 Scene·좌표·랜드마크·제품 SKU 일치와 권리 확인.

### 07 — ONE SEOUL

- Reference principle: Color Your Seoul의 일관성과 IISE의 전환 증거를 `두 장면이 한 컬렉션으로 회수`되는 기능에만 적용한다.
- Required asset role: `ONE SEOUL` — DAY/NIGHT Scene Pair, Logo Pair, 실제 Product Application Pair.
- Native Text:
  - `SEOUL : DAY & NIGHT`
  - `TWO SCENES. ONE SEOUL.` — Working 1회 후보, Final Slogan 자동 확정 금지
  - **DAY와 NIGHT, 서로 다른 두 장면이 하나의 서울을 이룹니다.**
  - `SEOUL HANGEUL LOGO`
  - **DAY와 NIGHT, 두 장면을 위해 서로 다른 ‘서울’ 한글 로고를 만들었습니다.**
- Visual grammar: `Scene↔Scene / Logo↔Logo / Product↔Product`를 동일 위계로 한 번씩 비교한다. 앞의 Project Mark와 Logo를 길게 재노출하지 않는다.
- Gate: DAY/NIGHT 실제 제품 적용 증거가 없으면 Logo 설명만 늘리지 않는다.

### 08 — PRODUCT

- Reference principle: 신:서울의 구매정보 완결성, thisisneverthat의 Lookbook→상품 연결, ADERERROR의 Editorial/Product Fact 분리, PAF의 상품 탐색 규율을 Product 안에만 적용한다.
- Required asset role: `PRODUCT PROOF`.
- P0 minimum proof: T-SHIRT·SWEATSHIRT·CAP 각각 `DAY/NIGHT / Front/Back / Signature Detail / Fit`. 제품군 사이의 증거량을 의도적으로 균등하게 맞춘다.
- Product order: `T-SHIRT → SWEATSHIRT → CAP`. 한 제품군을 끝내기 전에 다음 제품군으로 넘어가지 않는다.
- Native Text — 검증 Fact 유지:
  - T-SHIRT: **16수 싱글 텐타덤블 면 100% 원단을 사용했습니다. 전면에는 브랜드와 ‘서울’ DTF(필름 전사), 오른쪽 하단에는 실리콘 전사, 등판에는 DAY 또는 NIGHT의 실제 서울 장면과 좌표 DTF, 왼쪽 소매에는 Reflective(반사 전사)를 적용했습니다.**
  - SWEATSHIRT: **면 71%·폴리에스터 29% 특양면 원단을 사용했습니다. 전면 브랜드 실리콘과 소형 ‘서울’ DTF(필름 전사), 오른쪽 하단 실리콘 전사, 등판 장면 DTF, 왼쪽 소매 3M Reflective(반사 전사)를 적용했습니다.**
  - CAP: **16수 선워싱 면 트윌의 G14 베이스를 사용했습니다. 전면에는 DAY와 NIGHT 각각의 ‘서울’ 한글 로고, 측면에는 `+82 / DAY·NIGHT / 02 / SEOUL` 코드, 후면에는 `XXX STUDIO`를 자수로 적용했습니다.**
- Visual grammar: 제품명 → Fit/Lookbook → Front/Back → Detail → Verified Fact → Size. Editorial 컷과 사실 정보를 같은 이미지에 억지로 합치지 않는다.
- Gate: Current SKU Match, 실제 재고 상태, 실측, 판매 사이즈, 재생산 조건을 검증하기 전 미확정 값은 Consumer OFF. AI 이미지는 Product Proof로 사용 금지.

### 09 — SEOUL ON PEOPLE

- Reference principle: WOOYOUNGMI의 `서울을 사람·복식·태도로 보여주는 관점`만 적용한다.
- Required asset role: `PEOPLE` — 가장 강한 Full-width Editorial Lead 1장 + Archive Strip 또는 Contact Sheet 3–4장.
- Native Text: Body Copy 0. 필요할 때만 `DAY · SWEATSHIRT`, `NIGHT · T-SHIRT`, `DAY · CAP` 같은 제품 Metadata.
- Visual grammar: 모델 파일 나열이 아니라 하나의 착용 에디토리얼. Fashion Desire가 1순위이며 제품 상세 증거를 대체하지 않는다.
- Gate: 초상권, 광고·재편집 범위, 현행 SKU 일치 확인. 이름·계정·신체정보·후기·Crew·Ambassador 표현 금지. 변현수 자산 `HARD EXCLUDE` 유지.

### 10 — XXX STUDIO / ARCHIVE / CURRENT PROJECT

- Reference principle: 블루피치의 빠른 신뢰 형성 기능을 `BRAND PROVENANCE & CURRENT EXECUTION PROOF`로 변형한다.
- Required asset roles: `BRAND ARCHIVE`, `CURRENT VERIFICATION`. Maker Photo는 좋은 실제 사진과 권리가 있을 때만 선택 사용한다.
- Native Text — V0.8 Brand Copy 유지:
  - `XXX STUDIO`
  - `EXPERIENCE`
  - **XXX STUDIO는 패션을 통해 장면과 경험을 만드는 독립 브랜드입니다. 기획과 디자인은 XXX STUDIO가 진행하고, 제품 정보는 실제 생산 자료와 실물을 기준으로 안내합니다.**
  - 필요할 때만: **REPUBLIC OF KOREA TOUR는 그 안에서 한국의 도시와 장면을 다루는 프로젝트입니다.**
  - 과거 근거에는 `ARCHIVE`, 현재 검증에는 `CURRENT PROJECT`를 명시해 시점을 섞지 않는다.
- Evidence structure:
  1. XXX STUDIO와 KOREA TOUR의 관계
  2. 과거 실제 제품·작업지시서·소재·가공·생산 근거 — 반드시 `ARCHIVE`
  3. 현재 실제 재고, 현행 SKU 일치, 상태, 실측, 라벨·가공 확인
  4. 기존 재고 배정, 조건부 추가생산, 포장·배송, 교환·환불/A/S 실행 정보 — 확정 사실만
- Visual grammar: `Brand → Archive → Current Verification → Current Execution`의 명확한 시간 구분. 제조 감도용 Montage를 만들지 않는다.
- `NOT APPLICABLE / REJECT`: 없는 현재 제작 장면, 재연 공장 콘텐츠, 과거 생산사진의 현재화, 허위 연구·개발 서사.
- Gate: 각 Archive의 날짜·출처·당시 제품 일치와 각 Current 자료의 촬영일·SKU·실재고 일치를 확인한다.

### 11 — WHY NOW / WHY WADIZ

- Reference principle: 자리는 유지하되 구매 이유를 사실보다 먼저 쓰지 않는다.
- Required asset role: 별도 장식 이미지보다 실제 Offer·Current Execution Fact와 연결되는 Native Text.
- Native Text status: `DEFER / CONSUMER OFF`. V0.8 문구는 삭제하지 않고 후보로 보존하되 Final Copy로 잠그지 않는다.
  - WHY NOW 후보: **SEOUL : DAY & NIGHT는 XXX STUDIO가 앞서 선보인 KOREA TOUR의 첫 번째 챕터입니다. 이번 와디즈에서는 DAY와 NIGHT의 티셔츠, 스웨트셔츠, 캡을 한 자리에서 다시 소개하고, 보유 재고와 실제 주문 수량에 맞춰 필요한 제품을 준비합니다.**
  - WHY WADIZ 후보: **대량으로 먼저 생산하는 대신, 실제 주문을 확인한 뒤 필요한 수량을 준비합니다. 기존 재고는 우선 활용하고, 부족한 제품은 생산 가능 여부와 납기를 확인한 뒤 추가 제작합니다.**
  - 프로젝트 유형 확정 후 후보: **그래서 이번 프로젝트는 와디즈 프리오더 방식으로 제안합니다.**
- Visual grammar: 제품을 충분히 본 뒤 짧은 왼쪽 정렬 Native Text 2블록. `재고가 있다`는 사실 자체를 구매 설득으로 크게 사용하지 않는다.
- Gate: Offer, 실제 재고 배정, 추가생산 가능 조건, MOQ, Lead Time, Package, 발송 방식이 잠긴 뒤 문장 단위 Fact Check.

### 12 — OFFER / PACKAGE / COMMERCE

- Reference principle: 호담국의 명확한 단품/세트 선택, PAF의 정보 규율, 와디즈 공식 가이드의 필수정보 연결을 적용한다.
- Required asset role: `OFFER / PACKAGE` — 실제 제품과 확정 제공물만. Package는 제공 범위 확정 시에만 활성화한다.
- Page share: 최종 상세페이지의 약 25–30%를 실제 구매 구간으로 확보한다.
- First visible choice: `DAY / NIGHT / SEOUL — DAY + NIGHT`의 관계를 사용하되, 첫 선택은 핵심 2–3개로 단순화한다. 실제 리워드 행 수와 옵션은 03B에서 확정한다.
- Required Native Text modules:
  1. 리워드 구성
  2. 가격과 혜택
  3. 옵션 선택
  4. 제품 정보
  5. 사이즈 안내
  6. 재고 및 생산 방식
  7. 예상 발송 일정
  8. 배송 안내
  9. 교환·환불
  10. A/S
  11. FAQ
  12. 메이커 연락 및 서포터 커뮤니케이션
- Package Native Text — 활성 시에만:
  - `INVITATION TO KOREA TOUR`
  - **처음의 초대가 실제 패키지로 도착합니다.**
- Visual grammar: Neutral Commerce, 왼쪽 정렬, 짧은 문단, 표·목록. Skeleton을 Consumer에 길게 노출하지 않는다.
- Gate: 가격, 할인, 구성, 수량, 옵션, 실제 사이즈, 재고/추가생산, 발송일, 배송비, Package, 교환·환불/A/S, FAQ가 확정되기 전 숫자와 약속을 만들지 않는다.

### 13 — FINAL BOOKEND

- Reference principle: 외부 사례를 추가하지 않고 기존 수미상관을 유지한다.
- Required asset role: 실제 DAY/NIGHT Product가 Hero와 시각적으로 연결되는 마지막 이미지.
- Native Text:
  - `XXX STUDIO / EXPERIENCE`
  - `REPUBLIC OF KOREA TOUR · CHAPTER 01`
  - `SEOUL : DAY & NIGHT`
  - **서울의 낮과 밤을 입다**
  - CTA는 실제 와디즈 단계 확정 후 하나만 사용
- Visual grammar: 새로운 주장 없이 첫 제목과 실제 제품을 회수한다. 서울 한글 로고를 다시 크게 반복하지 않는다.
- Gate: Final Hero와 실제 CTA 상태가 정해진 뒤 첫 화면과 마지막 화면만 함께 재검토한다. `NEXT KOREA TOUR`는 후속 챕터 확정 전 Consumer OFF.

## 6. DAY / NIGHT Same-role Pair Lock

DAY와 NIGHT는 분위기만 대응시키지 않는다. Campaign Asset Cut 재선별에서 아래 역할을 각각 한 세트로 확보한다.

| DAY | NIGHT | 판정 기준 |
|---|---|---|
| DAY Scene | NIGHT Scene | 실제 서울 장면, 랜드마크 인지, 권리 |
| DAY Transformation | NIGHT Transformation | Scene·Landmark·Logo·Product 연결이 설명 없이 보이는가 |
| DAY Lookbook | NIGHT Lookbook | 같은 제품 역할과 유사한 증거 강도 |
| DAY Product | NIGHT Product | 현행 SKU, Front/Back, Detail, Fit |
| DAY Hangeul Logo | NIGHT Hangeul Logo | 같은 위계, 실제 제품 적용 증거 |

한쪽에 없는 역할을 다른 쪽의 분위기 이미지로 채우지 않는다. 같은 자산을 Macro 04/06/07/08에 반복 배치하지 않는다.

## 7. Product Proof P0 Lock

각 제품군의 최소 증거를 다음과 같이 잠근다.

| 제품군 | DAY/NIGHT | Front/Back | Detail | Fit | 필수 검증 |
|---|---|---|---|---|---|
| T-SHIRT | 필수 | 필수 | DTF·실리콘·반사 전사 | 필수 | 현행 SKU, 실측, 판매 사이즈, 재생산 조건 |
| SWEATSHIRT | 필수 | 필수 | DTF·실리콘·3M 반사 전사·원단 | 필수 | 현행 SKU, 실측, `750G` 의미, 재생산 조건 |
| CAP | 필수 | 전·측·후면 | 서울·도시코드·XXX STUDIO 자수, 원단 | 필수 | M/L 실측, 현행 SKU, 재생산 조건 |

Product Proof가 없으면 People, Logo, AI 이미지, 텍스트 Placeholder로 대체하지 않는다. 보유 자산으로 구성을 축소하고 Build Mode에 Gap을 남긴다.

## 8. Trust Lock — 과거와 현재의 분리

### ARCHIVE(과거 기록)

- 과거 실제 제품
- 당시 작업지시서·소재·가공 자료
- 당시 생산 근거와 제품 디테일
- 날짜·출처·당시 SKU를 함께 확인

### CURRENT VERIFICATION(현재 제품 검증)

- 현재 실제 보유 재고
- 현행 판매 SKU 일치
- 제품 상태 검수
- 실측
- 라벨·가공 확인

### CURRENT EXECUTION(현재 실행)

- 기존 재고 우선 배정 방식
- 추가생산 가능 여부와 조건
- 포장·배송 계획
- 교환·환불/A/S 기준

각 항목은 서로 다른 시점을 명시한다. 현재 확인되지 않은 정보는 Build Mode의 Gap으로만 남긴다.

## 9. Commerce Lock

- Offer와 Commerce는 하나의 Conversion Chapter다.
- Package는 독립 섹션이 아니라 확정 시 활성화되는 조건부 모듈이다.
- 첫 선택은 핵심 2–3개로 이해시킨다.
- 실제 리워드 행과 옵션 수는 PHASE 03B에서 확정한다.
- 가격·할인·수량·발송일을 만들지 않는다.
- Product Fact, Size, Delivery, Exchange/Refund, A/S, FAQ를 모두 Native Text로 제공한다.
- Commerce를 Skeleton과 면책문구로 길게 채우지 않는다.

## 10. 현재 가장 약한 구간 TOP 5

1. **제품군별 동등한 Product Proof** — T-SHIRT·SWEATSHIRT·CAP의 DAY/NIGHT·Front/Back·Detail·Fit이 아직 균등하지 않다.
2. **Brand Archive와 Current Verification의 실제 증거** — 현재 제작 장면이 아니라 과거/현재를 정확히 분리한 자료가 필요하다.
3. **DAY/NIGHT Same-role Pair와 Transition** — 분위기는 있으나 같은 역할 비교와 실제 시간 변화가 부족하다.
4. **People Art Direction** — Fashion Desire를 만드는 Lead와 Supporting 편집이 아직 잠기지 않았다.
5. **Offer·Commerce 실제 값** — 선택 구조는 있으나 가격·구성·재고·생산·배송·정책이 미확정이다.

Hero는 병렬 보류 항목이며 위 다섯 구조·증거 공백을 해결하지 못한다.
